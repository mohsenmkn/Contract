# راهنمای فرانت‌اند

رابط کاربری سامانه با Vue 3، Vite، PrimeVue و Tailwind CSS ساخته شده است. درخواست‌ها با Axios به Laravel API ارسال می‌شوند؛ Pinia وضعیت مشترک نشست، مجوزها و داده‌های صفحه را نگه می‌دارد.

## نصب و اجرا

نیازمندی Node.js طبق `package.json`: نسخهٔ ۲۰٫۱۹ یا جدیدتر، یا ۲۲٫۱۲ یا جدیدتر.

```powershell
npm install
```

API را در `Front/.env` مشخص کنید:

```env
VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1
```

سپس:

```powershell
npm run dev
npm run build
npm run preview
```

مقدار پیش‌فرض API در `src/api/axios.js` برابر مسیر نسبی `/api/v1` است. در استقرار، URL باید به نشانی HTTPS صحیح API اشاره کند.

## ساختار کد

- `src/views/`: صفحه‌های مسیریابی‌شده، گروه‌بندی‌شده بر اساس قابلیت.
- `src/components/`: اجزای مشترک و اجزای گردش قرارداد.
- `src/stores/`: وضعیت Pinia مانند نشست، قرارداد، امضا و ضمانت.
- `src/api/`, `src/services/`: لایهٔ ارتباط با API.
- `src/router/`: مسیرها، عنوان‌ها و نگهبان دسترسی.
- `src/config/menu.js`: منوی ناوبری.
- `src/composables/`: منطق مشترک قالب‌بندی، مجوز و دامنه.

## تجربه بر اساس نقش

- ورود، پروفایل و تغییر گذرواژه در بخش احراز هویت.
- کاربران واحد صفحهٔ داشبورد واحد و فهرست قراردادهای مجاز واحد خود را می‌بینند.
- کارشناس حقوقی و مدیر قراردادها صفحه‌های متناسب با بازبینی و مدیریت پرونده را دارند.
- پیمانکار فقط پرتال و قراردادهای مرتبط با خود را می‌بیند؛ صفحهٔ تاریخچهٔ داخلی برای او فعال نیست.
- مدیرعامل، عضو هیئت‌مدیره و معاون مالی داشبورد اجرایی و پیوند امضاهای در انتظار دارند.
- مجوز صفحه در `route.meta.permission` و فیلتر منو در `src/config/menu.js` تعریف می‌شود. کنترل امنیت نهایی باید سمت API نیز اعمال شود.

## صفحه‌های اصلی

| مسیر مفهومی | گروه صفحه |
|---|---|
| قراردادها | فهرست، ثبت/ویرایش یکپارچه، جزئیات، بررسی حقوقی و تنظیمات قرارداد |
| امضاها | فهرست امضاهای در انتظار، جزئیات سند، OTP و مدیریت تصاویر امضا |
| ضمانت‌نامه‌ها | فهرست، ایجاد، جزئیات و میز دریافت حضوری |
| سازمان | فهرست واحدها و نگاشت نقش‌ها/امضاکنندگان واحد |
| طرف‌های قرارداد، الحاقیه، صورت‌وضعیت و پرداخت | فرم‌ها و فهرست‌های وابسته به پرونده |
| کاربران و دسترسی | کاربران، نقش‌ها، گروه‌ها، نمایه و تنظیمات حساب |

## چاپ و سربرگ

صفحهٔ جزئیات قرارداد، نسخهٔ چاپی را جدا از منوی برنامه می‌سازد. سربرگ از تنظیمات قرارداد بارگیری می‌شود و می‌تواند تصویر صفحهٔ A4 یا سربرگ نواری باشد. برای چاپ رنگ و تصویر پس‌زمینه، گزینهٔ چاپ پس‌زمینه‌ها را در dialog مرورگر فعال کنید. امضای ثبت‌شدهٔ افراد باید توسط مدیر کل در بخش دارایی امضا تعریف شده باشد.

## نقش‌ها و فارسی‌سازی

شناسهٔ نقش لاتین از API/RBAC دریافت و ذخیره می‌شود؛ عنوان نمایشی فارسی از اطلاعات نقش در backend می‌آید. در صفحهٔ کاربران نقش را hard-code نکنید. برای مجوز جدید، مقدار را در backend تعریف کنید و آن را در Router، منو و کنترل نمایشی متناظر مصرف کنید؛ پنهان‌کردن دکمه جایگزین مجوز سمت سرور نیست.

## صحت و عیب‌یابی

- `npm run build`: ساخت production.
- `npm test`: اجرای آزمون navigation تعریف‌شده در همین package.
- خطای CORS یا شبکه: `VITE_API_BASE_URL`، پورت API، CORS و HTTPS را بررسی کنید.
- خطای 403: نقش و مجوزهای کاربر و همچنین تعلق پرونده به واحد/پیمانکار را بررسی کنید.
- فیلد تاریخ خالی: مقدار پاسخ API و parser تاریخ صفحه را بررسی کنید؛ API تاریخ را به قالب استاندارد میلادی برمی‌گرداند و نمایش UI می‌تواند شمسی باشد.
