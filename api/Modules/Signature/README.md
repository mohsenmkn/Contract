# ماژول امضا (Signature)

## هدف
ساخت و مدیریت اسلات‌های امضا، ارائهٔ امضاهای در انتظار، درخواست و اعتبارسنجی OTP، ثبت امضای سند و مدیریت تصویر امضای کاربران.

## مسیرهای اصلی
- `GET /api/v1/signatures/pending`, `GET /api/v1/signatures/{signature}`.
- `POST /api/v1/signatures/{signature}/request-otp`, `/verify-and-sign`, `/reject`.
- مسیرهای دارایی امضا در `/api/v1/signature-assets/*` برای وضعیت و نگهداری تصویر امضای کاربر.
- سرویس‌های اصلی: `SigningService.php`, `OtpService.php`; پیکربندی گروه/مرحله و نقش امضاکننده در `api/config/signing.php`.
- فرانت: `Front/src/views/Signature/PendingSignatures.vue`, `SignatureDetail.vue`, `SignatureAssets.vue`.

## مراحل و ضوابط
گروه‌های امضا شامل پیمانکار، واحد، حقوقی و مدیران مجاز است. پیمانکار برای امضا با OTP احراز می‌شود. هر کاربر داخلی برای امضای معتبر باید اسلات مجاز و تصویر امضای تعریف‌شده داشته باشد؛ مدیریت تصویر با مدیر کل سامانه است. تغییر متن قرارداد می‌تواند اسلات/امضاهای قبلی را باطل کند.

## محرمانگی
نمایش سند، اسلات و فایل امضا باید همزمان مالکیت/تعلق قرارداد، نقش امضاکننده و مجوز را کنترل کند. OTP را در log یا پاسخ API افشا نکنید.
